Hardcharger's ADBC driver is one C shared library, `libadbc_driver_hardcharger`, built from the
same Go code for every platform. Any [ADBC driver manager](https://arrow.apache.org/adbc/)
(C/C++, Go's `drivermgr`, R's `adbcdrivermanager`, Rust's `adbc_driver_manager`, Python's, ...)
loads it by name once its **driver manifest**, `hardcharger.toml`, is in a directory the driver
manager searches.

## Install the driver

GizmoData's ADBC driver installer downloads the latest release's library for your platform,
checks it against the release's checksums, and writes the manifest to your user's driver
directory:

```console test server=none title="Linux, macOS"
$ curl https://install.adbc.gizmodata.com/hardcharger | sh
…
==> Installed the Hardcharger ADBC driver …
  library:  …/hardcharger/…/libadbc_driver_hardcharger.so
  manifest: …/.config/adbc/drivers/hardcharger.toml
  driver = "hardcharger"
…
```

```powershell title="Windows (PowerShell)"
irm https://install.adbc.gizmodata.com/hardcharger.ps1 | iex
```

It installs into the directory every driver manager searches for your user:

| Platform | Directory |
|---|---|
| Linux | `~/.config/adbc/drivers/` (`$XDG_CONFIG_HOME/adbc/drivers/`) |
| macOS | `~/Library/Application Support/ADBC/Drivers/` |
| Windows | `%LOCALAPPDATA%\ADBC\Drivers\` |

Options go to the `sh` that runs the script:

```bash title="Options (Linux, macOS)"
# A pinned release (2.6.1 or later: the first with checksums)
curl https://install.adbc.gizmodata.com/hardcharger | ADBC_VERSION=2.6.1 sh
# For every user: /etc/adbc/drivers, /Library/Application Support/ADBC/Drivers
curl https://install.adbc.gizmodata.com/hardcharger | sudo sh -s -- --system
# Another directory: driver managers search it when it is on ADBC_DRIVER_PATH
curl https://install.adbc.gizmodata.com/hardcharger | sh -s -- --dir ~/my-drivers
# Remove it
curl https://install.adbc.gizmodata.com/hardcharger | sh -s -- --uninstall
```

The same installer sets up GizmoData's other ADBC drivers (`chargewire`, `gizmosql`, `oracle`,
`db2` and `quack`); its [README](https://github.com/gizmodata/adbc-install#readme) lists every
option, the PowerShell ones included.

### From the Python package

With the Python package installed (`pip install adbc-driver-hardcharger`), you already have the
library, inside the wheel, and the package writes a manifest that points at it:

```console test server=none
$ python3 -m adbc_driver_hardcharger.manifest --print | grep -E '^(name|entrypoint) ='
name = 'Hardcharger'
entrypoint = 'AdbcDriverHardchargerInit'
$ python3 -m adbc_driver_hardcharger.manifest --dir drivers > /dev/null
$ ls drivers
hardcharger.toml
```

Without `--dir` it writes `hardcharger.toml` to your user's driver directory (the table above),
the same file the installer writes, so whichever ran last is the one loaded. Use it for programs
that run in that Python environment: the manifest stops working when the environment is removed.

## Load it by name

Every driver manager then finds it as `hardcharger`, with the same options in every language.
Through Python's driver manager (`pip install adbc-driver-manager pyarrow`):

```python test
import adbc_driver_manager.dbapi

with adbc_driver_manager.dbapi.connect(driver="hardcharger", db_kwargs={
        "uri": "hardcharger://localhost?tls=false", "username": "hardcharger", "password": "change-me",
        "adbc.hardcharger.query_tag": '{"app": "driver-manager"}'}) as conn:
    with conn.cursor() as cur:
        cur.execute(operation="SELECT 42 AS answer")
        print(cur.fetchone())
```

```text output
(42,)
```

`driver` also takes a manifest's path (`driver="drivers/hardcharger.toml"`), for a manifest that
isn't in a searched directory.

In C, the same takes `AdbcDriverManagerDatabaseSetLoadFlags(&database, ADBC_LOAD_FLAG_DEFAULT, &error)`
and then `AdbcDatabaseSetOption(&database, "driver", "hardcharger", &error)`, then the `uri`,
`username` and `password` options. Without the load flags, the C driver manager doesn't search
the driver directories, and loading `hardcharger` fails.
[`examples/c/hello.c`](https://github.com/gizmodata/hardcharger-adbc/blob/main/examples/c/hello.c)
is a complete program, and hardcharger-adbc's CI builds and runs it against a real server. Go's
[`drivermgr`](https://pkg.go.dev/github.com/apache/arrow-adbc/go/adbc/drivermgr) (cgo) searches
them by default: pass `"driver": "hardcharger"` with the other options to
`drivermgr.Driver{}.NewDatabaseWithContext`. (A Go program can also import the driver itself,
with no installer: see [Go](/clients/go/).) R and Rust load it the same way, by the name
`hardcharger`.

The options are listed on the [Go page](/clients/go/#options): they are the same everywhere,
since every language runs the same driver.

<Aside type="note">
Arrow arrives from the driver as Arrow's C data interface, so each language gets its own Arrow
objects (`arrow::RecordBatchReader`, `nanoarrow`, R's `nanoarrow_array_stream`, Rust's
`RecordBatchReader`) with no copy.
</Aside>
