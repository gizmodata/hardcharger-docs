`hardcharger` is Hardcharger's command-line client. Run it with no statement for an interactive
shell, or give it SQL to run and print. It ships beside `hardcharger-server` (in the tarballs'
`bin/`, the Windows zips and the image). The [CLI reference](/reference/cli/) lists every option and dot command.

## Connect

```console test
$ export HARDCHARGER_PASSWORD='change-me'
$ hardcharger --host localhost --tls=false --username hardcharger --command "SELECT HARDCHARGER_USER() AS me"
┌─────────────┐
│     me      │
│   varchar   │
├─────────────┤
│ hardcharger │
├─────────────┤
│ 1 row       │
└─────────────┘
```

| What | Option | Environment |
|---|---|---|
| Server | `--host`, `-h` (default `localhost`), `--port`, `-p` (default 31337) | `HARDCHARGER_HOST`, `HARDCHARGER_PORT` |
| User | `--username`, `-u` | `HARDCHARGER_USER` |
| Password | asked for, or `--password`/`-W` to force the prompt | `HARDCHARGER_PASSWORD` |
| TLS | on by default; `--tls=false` for plain HTTP (a server without `--tls-cert`, like the ones on these pages); `--tls-roots FILE`, `--tls-skip-verify` | `HARDCHARGER_TLS` (`true` or `false`), `HARDCHARGER_TLS_ROOTS` |
| Mutual TLS | `--mtls-cert FILE`, `--mtls-key FILE` | |
| SSO | `--auth-type external` ([browser sign-in](/guides/sso/#browser-sign-in)) | |
| Host, port and TLS in one URI | `hardcharger://HOST[:PORT][/PREFIX][?tls=false]` (or `--uri`): HTTPS unless `?tls=false`, port 31337, as in the [Python](/clients/python/) and [Go](/clients/go/) drivers. `tls` is its only parameter; the user and the other settings are the flags above | |

`HARDCHARGER_PASSWORD` is the user's own password; the client never falls back to the server's
`HARDCHARGER_ADMIN_PASSWORD`.

The client uses TLS unless told otherwise, as the drivers do. Against a server without TLS it
stops, sends nothing in plaintext, and says what to add:

```console test exit=1
$ hardcharger --host localhost --username hardcharger --command "SELECT 1"
Error: The server at localhost:31337 speaks plain HTTP, not TLS. Add --tls=false (or ?tls=false in a hardcharger:// URI) to connect without encryption.
```

## The interactive shell

```console test kind=repl
$ hardcharger --host localhost --tls=false --username hardcharger
Password:
Hardcharger Client …
Connected to localhost:31337
Type '.help' for help, '.quit' to exit.

my.main> CREATE TABLE trips AS SELECT * FROM (VALUES (1, 'Boston', 12.5), (2, 'Denver', 30.0)) t(id, city, miles);
OK, 2 rows affected
my.main> SELECT city, miles FROM trips ORDER BY miles DESC;
┌─────────┬──────────────┐
│  city   │    miles     │
│ varchar │ decimal(3,1) │
├─────────┼──────────────┤
│ Denver  │         30.0 │
│ Boston  │         12.5 │
├─────────┴──────────────┤
│ 2 rows  2 columns      │
└────────────────────────┘
my.main> .quit
```

- **Color** at a terminal only: prompts, errors and highlighting are plain in pipes and files,
  and `NO_COLOR` (set to anything) turns color off everywhere.
- **Line editing** with history (`~/.hardcharger_history`), tab completion of SQL keywords,
  catalogs, schemas, tables and columns, and syntax highlighting.
- **A pager** for results longer than the screen (`.pager on|off|N`).
- **Ctrl-C** cancels the running statement on the server, and the shell goes on.
- **A lost session is reopened.** If the server forgot the session (idle too long, restarted) or
  an administrator killed it, the client opens a new one and says so; temporary tables and
  session settings don't survive that.
- **`~/.hardchargerrc`** runs at startup (`--init FILE` for another, `--no-init` for none):
  `.mode`, `.timer on`, `SET hardcharger.query_tag = …`.

The prompt is the current `catalog.schema`.

## Scripts

One statement with `--command` (`-c`), a file with `--file` (`-f`), or SQL on standard input from
a heredoc or a pipe:

```console test
$ export HARDCHARGER_PASSWORD='change-me'
$ hardcharger --host localhost --tls=false --username hardcharger --quiet <<'SQL'
CREATE OR REPLACE TABLE trips AS SELECT * FROM (VALUES (1, 'Boston', 12.5), (2, 'Denver', 30.0)) t(id, city, miles);
INSERT INTO trips VALUES (3, 'Austin', 8.5);
SELECT count(*) AS trips, sum(miles) AS miles FROM trips;
SQL
OK, 2 rows affected
OK, 1 row affected
┌────────┬───────────────┐
│ trips  │     miles     │
│ bigint │ decimal(38,1) │
├────────┼───────────────┤
│      3 │          51.0 │
├────────┴───────────────┤
│ 1 row  2 columns       │
└────────────────────────┘
$ echo "SELECT city FROM trips WHERE miles > 10 ORDER BY city" | hardcharger --host localhost --tls=false --username hardcharger --csv
city
Boston
Denver
```

- The exit status is **1 when a statement fails** (or a dot command does), so scripts and CI jobs
  notice. `--bail` stops at the first failure; without it the script goes on and still exits 1.
- `--quiet` drops the banner and informational messages; `--echo` prints each statement first.
- `--output FILE` (or `.output FILE`) writes results to a file.

```console test
$ export HARDCHARGER_PASSWORD='change-me'
$ hardcharger --host localhost --tls=false --username hardcharger --quiet --command "SELECT * FROM missing_table" 2> error.txt; echo "exit status $?"
exit status 1
$ grep -o "Table with name missing_table does not exist" error.txt
Table with name missing_table does not exist
```

Comments (`--` and `/* */`) anywhere in a script are fine, including after the last statement.

When the server stops accepting the sign-in (the user's password changed, the user was dropped
or disabled, a scoped token was revoked or expired), the client says why, from the refusal's
[`reason`](/reference/errors/#invalid_token-reasons), and doesn't retry with the old credentials.
Here an administrator changes `joe`'s password while joe's script runs:

```console test profile=rbac
$ export HARDCHARGER_PASSWORD='change-me'
$ hardcharger --host localhost --tls=false --username hardcharger --quiet --command "CREATE USER joe WITH PASSWORD 'old-secret'" > /dev/null
$ { echo "SELECT 1 AS before;"; sleep 2
    hardcharger --host localhost --tls=false --username hardcharger --quiet --command "ALTER USER joe WITH PASSWORD 'new-secret'" > /dev/null
    sleep 2; echo "SELECT 2 AS after;"; } | HARDCHARGER_PASSWORD='old-secret' hardcharger --host localhost --tls=false --username joe --csv --quiet; echo "exit status $?"
before
1
Error: The server no longer accepts this sign-in: the user's password or credentials changed (credentials_changed). Sign in again (.connect).
exit status 1
```

A session an administrator ended with [`KILL SESSION`](/reference/sql/#kill-session) is different:
the sign-in still stands, so the client opens a new session and says why. The statement that met
the ended session fails, and the next ones run in the new session:

```console test profile=rbac
$ export HARDCHARGER_PASSWORD='change-me'
$ { echo "SELECT 1 AS before;"; sleep 2
    ID=$(hardcharger --host localhost --tls=false --username hardcharger --quiet --csv \
      --command "SELECT session_id FROM hardcharger_sessions() WHERE username = 'joe' ORDER BY start_time DESC LIMIT 1" | tail -1)
    hardcharger --host localhost --tls=false --username hardcharger --quiet --command "KILL SESSION '$ID'" > /dev/null
    sleep 1; echo "SELECT 2 AS after;"; echo "SELECT 3 AS again;"; } | HARDCHARGER_PASSWORD='new-secret' hardcharger --host localhost --tls=false --username joe --csv --quiet; echo "exit status $?"
before
1
Warning: the server ended this session: an administrator ended it (killed); a new session is open. Temporary tables and session settings are gone.
Error: This session has been killed by an administrator (reason: killed). Sign in again and open a new session to re-authenticate.
again
3
exit status 1
```

## Output modes

`--csv`, `--json`, `--markdown`, `--table` and `--box` (the default) pick a mode at the start;
`.mode` picks any of them in a session or script:

```console test
$ export HARDCHARGER_PASSWORD='change-me'
$ hardcharger --host localhost --tls=false --username hardcharger --quiet --command "CREATE TABLE IF NOT EXISTS trips AS SELECT * FROM (VALUES (1, 'Boston', 12.5), (2, 'Denver', 30.0)) t(id, city, miles)" > /dev/null
$ printf '.mode json\nSELECT * FROM trips WHERE id < 3 ORDER BY id;\n' | hardcharger --host localhost --tls=false --username hardcharger --quiet
[
  {"id": 1, "city": "Boston", "miles": 12.5},
  {"id": 2, "city": "Denver", "miles": 30.0}
]
$ printf '.mode markdown\nSELECT * FROM trips WHERE id < 3 ORDER BY id;\n' | hardcharger --host localhost --tls=false --username hardcharger --quiet
| id | city   | miles |
| -- | ------ | ----- |
| 1  | Boston | 12.5  |
| 2  | Denver | 30.0  |
$ printf '.mode line\nSELECT * FROM trips WHERE id = 1;\n' | hardcharger --host localhost --tls=false --username hardcharger --quiet
   id = 1
 city = Boston
miles = 12.5
```

| Mode | Prints |
|---|---|
| `box` | Unicode table with column types and a row count (the default) |
| `table` | the same with ASCII borders |
| `csv`, `tabs`, `list` | comma-, tab- or `\|`-separated values (`.separator` changes them) |
| `json`, `jsonlines` | a JSON array, or one object per line |
| `markdown` | a Markdown table |
| `line` | one `column = value` line per column, rows separated by a blank line |
| `html`, `latex` | an HTML or LaTeX table |
| `insert` | `INSERT` statements |
| `quote` | values as SQL literals |
| `ascii` | values separated by the ASCII unit and record separators |
| `trash` | nothing (run for the side effects or the timing) |

Machine-readable modes print no row-count line into files and pipes, so `--json | jq` works.
`--no-header` drops headers, `--null TEXT` sets how NULL prints.

## Dot commands

| Command | Does |
|---|---|
| `.tables [PATTERN] [--flat]` | List tables, as a tree or flat |
| `.schema [PATTERN]`, `.describe TABLE`, `.catalogs` | Show schemas, a table's columns, the catalogs |
| `.mode MODE`, `.headers on\|off`, `.nullvalue TEXT`, `.separator COL [ROW]` | Output format |
| `.maxrows [N]`, `.maxwidth [N]`, `.pager on\|off\|N` | Long and wide results |
| `.output [FILE]`, `.once FILE` | Write results to a file (`.once`: only the next one) |
| `.export_last [FILE]` | Save the last result as an Arrow IPC file (default `~/.hardcharger_last_result.arrow`) |
| `.last` | Show the last result again |
| `.read FILE` | Run a SQL file |
| `.timer on\|off`, `.echo on\|off`, `.bail on\|off` | Timing, echo, stop on error |
| `.connect URI [USER [PASSWORD]]` or `.connect HOST PORT USER` | Connect elsewhere |
| `.show`, `.about` | Current settings; version and server info |
| `.refresh` | Reload the completion cache |
| `.cd DIR`, `.shell CMD` | Change directory; run a shell command |
| `.prompt MAIN [CONT]` | Set the prompts |
| `.help [PATTERN]`, `.quit`, `.exit` | Help; leave |

## Large results

The client reads a large result over up to 8 connections at once, in the same order
([partitions](/concepts/warp-sql/#partitioned-results)); small results come as one stream.
`--result-partitions N` (or `HARDCHARGER_RESULT_PARTITIONS`) changes the 8; `1` reads over one
connection.

## Tags

`--session-tag JSON` and `--query-tag JSON` (or `HARDCHARGER_SESSION_TAG`,
`HARDCHARGER_QUERY_TAG`) tag what the client runs, for [instrumentation](/guides/instrumentation-and-audit/).

## Coming from gizmosql_client

`hardcharger` is GizmoSQL 1.x's `gizmosql_client`, on Warp SQL, with the same options under
Hardcharger's names. [Coming from GizmoSQL](/get-started/coming-from-gizmosql/#the-command-line-client)
maps them and lists what behaves differently.
