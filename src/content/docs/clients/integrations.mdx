## Drivers

### Python, Go and ADBC driver

`adbc-driver-hardcharger`: query Hardcharger from Python, Go, C/C++, R, Rust or any ADBC
language. Python gets DB-API 2.0 with Arrow results, Go programs import it directly, and C/C++, R
and Rust load it through an ADBC driver manager, by the name `hardcharger`, after a one-line
install.

```bash title="Install"
# Python
pip install adbc-driver-hardcharger
# Go
go get github.com/gizmodata/hardcharger-adbc/go/v2
# Any ADBC driver manager (C/C++, R, Rust, ...) on Linux or macOS
curl https://install.adbc.gizmodata.com/hardcharger | sh
```

```powershell title="Install for any ADBC driver manager (Windows)"
irm https://install.adbc.gizmodata.com/hardcharger.ps1 | iex
```

```python test title="query.py"
from adbc_driver_hardcharger import dbapi as hardcharger

with hardcharger.connect(uri="hardcharger://localhost?tls=false", username="hardcharger", password="change-me") as conn:
    with conn.cursor() as cur:
        cur.execute(operation="SELECT 42 AS answer, ? AS greeting", parameters=["hello"])
        print(cur.fetch_arrow_table())
```

```text output title="Output"
pyarrow.Table
answer: int32
greeting: string
----
answer: [[42]]
greeting: [["hello"]]
```

Python 3.11 or later. `?tls=false` is for a local server on plain HTTP; production servers use
TLS, so leave it out there. The installer puts the native driver and its manifest where every ADBC
driver manager looks, so `driver = "hardcharger"` loads it; it also installs GizmoData's other ADBC
drivers (`chargewire`, `gizmosql`, `oracle`, `db2` and `quack`).

### ODBC driver

The Hardcharger ODBC driver, for any ODBC application (and Python through `pyodbc`), with native
Chargewire and Arrow streaming. A code-signed Windows x64 MSI, and native libraries for macOS 15
or later on Apple Silicon and Linux x64/ARM64 with glibc 2.39 or later.

On Windows, the MSI installs and registers the driver. On Linux, install unixODBC and `pyodbc`,
then download the driver and register it in your `~/.odbcinst.ini`:

```bash title="Install (Debian, Ubuntu)"
sudo apt-get install unixodbc
pip install pyodbc
```

```bash test server=none title="Download and register the driver (Linux)"
arch=$(dpkg --print-architecture)   # amd64 or arm64
mkdir -p "$HOME/.local/hardcharger-odbc"
curl -fsSL "https://github.com/gizmodata/hardcharger-odbc-driver/releases/latest/download/hardcharger-odbc-linux-$arch.tar.gz" \
  | tar -xz -C "$HOME/.local/hardcharger-odbc"
cat >> "$HOME/.odbcinst.ini" <<EOF
[Hardcharger ODBC Driver]
Description = Hardcharger ODBC Driver (Chargewire)
Driver = $HOME/.local/hardcharger-odbc/lib/libhardcharger-odbc.so
EOF
```

```python test env=odbc title="query.py"
import pyodbc

with pyodbc.connect(
    "Driver={Hardcharger ODBC Driver};"
    "uri=hardcharger://localhost?tls=false;"
    "uid=hardcharger;pwd=change-me;",
    autocommit=True,
) as connection:
    row = connection.execute(
        "SELECT CAST(? AS VARCHAR), 42", "hello"
    ).fetchone()
    print(row)
```

```text output title="Output"
('hello', 42)
```

The example uses `tls=false` for a local development server. Leave it out to use verified TLS in
production, and set `trustedCerts` for a private CA.

[GitHub](https://github.com/gizmodata/hardcharger-odbc-driver) ·

[Windows MSI](https://github.com/gizmodata/hardcharger-odbc-driver/releases/latest/download/Hardcharger-ODBC-Driver-x64.msi)

### JDBC driver

`hardcharger-jdbc`: Hardcharger for Java applications, DBeaver and other JDBC tools, in one jar.

```xml title="pom.xml: the Maven dependency"
<dependency>
  <groupId>com.gizmodata</groupId>
  <artifactId>hardcharger-jdbc</artifactId>
  <version><!-- the release version --></version>
</dependency>
```

```java test title="Query.java"
Properties properties = new Properties();
properties.setProperty("user", "hardcharger");
properties.setProperty("password", "change-me");
properties.setProperty("useEncryption", "false"); // plain HTTP on localhost
try (Connection connection = DriverManager.getConnection("jdbc:hardcharger://localhost", properties);
     ResultSet rows = connection.createStatement().executeQuery("SELECT 42 AS answer")) {
  rows.next();
  System.out.println(rows.getInt("answer"));
}
```

```text output title="Output"
42
```

Java 17 or later. Leave out `useEncryption=false` for a production server, which uses TLS. Bulk
ingest has no JDBC API; use the ADBC driver for loads.

### QGIS plugin

`qhardcharger`: show Hardcharger spatial tables and custom SQL in QGIS 4 (4.2.3 or later). Install
it from Plugins → Manage and Install Plugins.

<Steps>

1. In QGIS 4.2.3 or later, choose **Plugins → Manage and Install Plugins**, search for
   `qhardcharger` and click **Install Plugin**. Accept the dependency download when the plugin is
   first activated.
2. Choose **Plugins → Hardcharger → Add Hardcharger layer**.
3. **Host** `localhost`, **Port** `31337`. Clear **Use TLS (HTTPS)** only for a local server
   without TLS; production servers use TLS.
4. **Auth type** `Password`. Under **Credentials**, create a Basic authentication configuration
   with user `hardcharger` and password `change-me`. QGIS Auth Manager stores it encrypted.
5. Click **Connect & list tables** and pick a `catalog.schema.table`, or choose **Custom SQL** and
   enter a `SELECT`. Set **Geometry CRS** to the actual CRS of your source coordinates.
6. Click **Add Layer**.

</Steps>

Offline, download the ZIP and use **Install from ZIP** in the same dialog:

```console test server=none title="Download the plugin"
$ curl -L --fail -o qhardcharger.zip https://github.com/gizmodata/qhardcharger/releases/latest/download/qhardcharger.zip
…
```

To add a layer from QGIS's Python console:

```python title="QGIS Python console"
from qgis.core import QgsProject, QgsProviderRegistry, QgsVectorLayer

metadata = QgsProviderRegistry.instance().providerMetadata("hardcharger")
uri = metadata.encodeUri({
    "host": "db.example.com",
    "port": "31337",
    "authcfg": "abc1234",  # your QGIS Basic authentication config ID
    "schema": "main",
    "table": "cities",
    "epsg": "4326",        # the actual CRS of your source coordinates
})
layer = QgsVectorLayer(uri, "Cities", "hardcharger")
if not layer.isValid():
    raise RuntimeError("Check the Hardcharger entry in QGIS Log Messages")
QgsProject.instance().addMapLayer(layer)
```

For a local server without TLS, add `"use_tls": "0"`. Restart QGIS after upgrading the plugin.

[QGIS plugin repository](https://plugins.qgis.org/plugins/qhardcharger/) ·
[GitHub](https://github.com/gizmodata/qhardcharger)

## AI and agents

### Hardcharger MCP server

Explore and query Hardcharger from Claude Desktop, Claude Code and any MCP client. Add it to
Claude Code:

```bash title="Add the server to Claude Code"
claude mcp add hardcharger \
  -e HARDCHARGER_URI='hardcharger://localhost?tls=false' \
  -e HARDCHARGER_USERNAME=hardcharger \
  -e HARDCHARGER_PASSWORD=change-me \
  -- npx -y @gizmodata/hardcharger-mcp
```

To check the server without an MCP client, this script starts it as Claude Code does, with the
same settings, and runs one query over stdio:

```python test stop timeout=300 title="check_mcp.py: call the MCP server from a script"
import json
import os
import subprocess

env = dict(os.environ, HARDCHARGER_URI="hardcharger://localhost?tls=false",
           HARDCHARGER_USERNAME="hardcharger", HARDCHARGER_PASSWORD="change-me")
server = subprocess.Popen(args=["npx", "-y", "@gizmodata/hardcharger-mcp"], env=env, text=True,
                          stdin=subprocess.PIPE, stdout=subprocess.PIPE)

def send(message):
    server.stdin.write(json.dumps(obj={"jsonrpc": "2.0", **message}) + "\n")
    server.stdin.flush()

def call(number, method, params):
    send(message={"id": number, "method": method, "params": params})
    return json.loads(s=server.stdout.readline())["result"]

info = call(number=1, method="initialize", params={"protocolVersion": "2025-06-18", "capabilities": {},
                                                   "clientInfo": {"name": "check", "version": "1.0"}})
print(info["serverInfo"]["name"])
send(message={"method": "notifications/initialized"})
result = call(number=2, method="tools/call", params={"name": "run_query", "arguments": {"sql": "SELECT 42 AS answer"}})
print(result["content"][0]["text"])
server.stdin.close()
server.wait()
```

```text output title="Output"
@gizmodata/hardcharger-mcp
| answer |
| --- |
| 42 |

1 row returned · … ms
```

Node 22.19 or later for `npx`; Claude Desktop can install the `.mcpb` extension instead, with no
Node needed. For a production server, which uses TLS, set `HARDCHARGER_URI` to
`hardcharger://<host>` without `?tls=false`.

[GitHub](https://github.com/gizmodata/hardcharger-mcp) ·

### PDF Loader

Load PDF manuals into Hardcharger, so SQL clients and MCP agents can search the text and fetch the
originals.

```bash title="Install"
pip install hardcharger-pdf-loader
```

The loader reads its connection from a `.env` file in the working directory (or the environment).
`HARDCHARGER_CATALOG` is an attached, persistent catalog: here `my`, the server's `my.duckdb`. TLS
is on by default; `HARDCHARGER_USE_TLS=false` is for a local server on plain HTTP.

```dotenv test file=.env server=none title=".env"
HARDCHARGER_HOSTNAME=localhost
HARDCHARGER_PORT=31337
HARDCHARGER_USERNAME=hardcharger
HARDCHARGER_PASSWORD=change-me
HARDCHARGER_CATALOG=my
HARDCHARGER_USE_TLS=false
```

A one-page PDF to load (any PDFs in `source_pdf_files` will do):

```python test env=pdf-loader server=none title="make_sample_pdf.py"
import pathlib

import pymupdf

pathlib.Path("source_pdf_files").mkdir()
doc = pymupdf.open()
page = doc.new_page()
page.insert_text(point=(72, 72), text="Check the hydraulic pump relief valves every 500 hours.")
doc.save(filename="source_pdf_files/pump-manual.pdf")
```

Load it, list what is loaded, and search:

```console test env=pdf-loader timeout=600 title="Load the PDFs"
$ hardcharger-pdf-loader load --source-dir source_pdf_files
…
status            size chunks  pages w/text   ocr       chars    secs  file
loaded … pump-manual.pdf
$ hardcharger-pdf-loader list
         size  pages w/text       chars chunks revealed  loaded_at (UTC)      file
… pump-manual.pdf
1 document(s)
$ hardcharger-pdf-loader search "hydraulic pump relief valves" --ranked --limit 5
== pump-manual.pdf — page 1 (score …)
   Check the hydraulic pump relief valves every 500 hours.
1 hit(s)
```

A DuckLake catalog can't hold the full-text index. For a DuckLake target, keep the index in an
attached DuckDB catalog:

```console test env=pdf-loader title="Build the full-text index"
$ export HARDCHARGER_PASSWORD='change-me'
$ hardcharger --host localhost --tls=false --username hardcharger --command "ATTACH 'search_index.duckdb' AS search_index"
OK
$ hardcharger-pdf-loader index --fts-catalog search_index
…
full-text index rebuilt over 1 page(s) in search_index.fts_pdf_fts_document_pages (index built over a copy of the page text in the 'duckdb' catalog 'search_index')
```

Python 3.11 to 3.15. Loading the `fts` extension needs an administrator; querying an existing
index does not. Rebuild the index (`hardcharger-pdf-loader index`) after changing the documents.

[GitHub](https://github.com/gizmodata/hardcharger-pdf-loader) ·
[PyPI](https://pypi.org/project/hardcharger-pdf-loader/)

### Ibis backend

Write Ibis dataframe expressions in Python and run them on Hardcharger as DuckDB SQL.

```bash title="Install"
pip install ibis-hardcharger
# The example starts a throwaway local server:
pip install hardcharger
```

The example starts its own server, in memory, and connects without TLS:

```python test server=none release env=ibis title="query.py"
import hardcharger
import ibis

with hardcharger.Server() as server:  # a throwaway server on this machine
    con = ibis.hardcharger.connect(
        host=server.host,
        port=server.port,
        user=server.username,
        password=server.password,
        use_encryption=False,  # the throwaway server speaks plain HTTP
    )
    trips = con.create_table(
        "trips",
        obj=ibis.memtable(
            {"city": ["Boston", "Denver", "Boston", "Austin"], "miles": [12.5, 30.0, 4.0, 8.5]}
        ),
    )
    by_city = (
        trips.group_by("city")
        .agg(trips=trips.count(), miles=trips.miles.sum())
        .order_by(ibis.desc("miles"))
    )
    print(by_city.to_pandas())
    con.disconnect()
```

```text output title="Output"
     city  trips  miles
0  Denver      1   30.0
1  Boston      2   16.5
2  Austin      1    8.5
```

Python 3.11 to 3.15, Ibis 12.0. TLS is on unless `use_encryption=False`, or `?tls=false` in a URL.
Python, pandas and PyArrow UDFs are not supported.

[GitHub](https://github.com/gizmodata/ibis-hardcharger) ·
[PyPI](https://pypi.org/project/ibis-hardcharger/)

### adbc-replicate-hardcharger

Copy whole schemas from Oracle, PostgreSQL, Snowflake, DuckDB or another Hardcharger, on a

```bash title="Install"
pip install "adbc-replicate-hardcharger[all]"   # or [oracle], [postgresql], [snowflake], [duckdb]
```

The example copies from a local DuckDB file, `shop.duckdb`. Make one:

```python test env=replicate title="make_source.py: a DuckDB file to copy"
import duckdb

with duckdb.connect(database="shop.duckdb") as con:
    con.execute(query="CREATE SCHEMA sales")
    con.execute(query="""
        CREATE TABLE sales.customers AS SELECT * FROM (VALUES
          (1, 'Ada', '123-45-6789'), (2, 'Grace', '987-65-4321')) t(id, name, ssn)
    """)
```

`replicate.yaml` copies the `sales` schema and hashes the `ssn` column inside the source, so the raw
values never leave it. `?tls=false` is for a local server without TLS; leave it out in production:

```yaml test file=replicate.yaml title="replicate.yaml"
version: 1
name: shop-to-hardcharger

source:
  type: duckdb
  path: ./shop.duckdb

target:
  type: hardcharger
  uri: hardcharger://localhost?tls=false
  username: hardcharger
  password: ${HARDCHARGER_PASSWORD}

objects:
  - db_schemas: [sales]

columns:
  - tables: [sales.customers]
    mask:
      ssn: hash

parallelism: 2
```

### dlt destination

Load anything [dlt](https://dlthub.com) can extract into Hardcharger, as Arrow over Chargewire.

```bash title="Install"
pip install dlt-hardcharger
```

`destination="hardcharger"` works with no import: dlt finds the destination through the package,
and reads its URL from `.dlt/secrets.toml` (or an environment variable). `?tls=false` is for a
local server without TLS; leave it out in production:

```toml test file=.dlt/secrets.toml title=".dlt/secrets.toml"
[destination.hardcharger]
credentials = "hardcharger://hardcharger:change-me@localhost:31337?tls=false"
```

Run a pipeline:

```python test env=dlt title="load.py"
import dlt

pipeline = dlt.pipeline(pipeline_name="from_secrets", destination="hardcharger", dataset_name="crm")
pipeline.run(data=[{"id": 1, "name": "Ada"}], table_name="contacts")
print(pipeline.dataset().contacts.select("id", "name").fetchall())
```

```text output title="Output"
[(1, 'Ada')]
```

Python 3.10 to 3.14, dlt 1.32.0 or later (below 2). TLS is on unless the URL says `?tls=false`.

[GitHub](https://github.com/gizmodata/dlt-hardcharger) ·
[PyPI](https://pypi.org/project/dlt-hardcharger/)

### DuckDB ADBC Scanner (Query.Farm)

Query Hardcharger from a local DuckDB with Query.Farm's `adbc_scanner` community extension and
the Hardcharger ADBC driver.

Install the DuckDB CLI and the driver, then register the driver so DuckDB finds it by the name
`hardcharger`. Keep that Python environment installed: the registration points at its driver
library. Or install the driver with `curl https://install.adbc.gizmodata.com/hardcharger | sh`
(Windows: `irm https://install.adbc.gizmodata.com/hardcharger.ps1 | iex`) instead of the
`adbc-driver-hardcharger` package and the registration step: DuckDB finds it by the same name,
with no Python environment behind it.

```bash title="Install"
pip install duckdb-cli==1.5.6 adbc-driver-hardcharger
```

```console test env=duckdb-adbc server=none title="Register the driver"
$ python -m adbc_driver_hardcharger.manifest
…/.config/adbc/drivers/hardcharger.toml
```

Save this as `query-farm.sql`. It attaches the server as `hc`, lists its tables, and runs a query
with a bound parameter on the server with `adbc_scan()`:

```sql test file=query-farm.sql title="query-farm.sql"
INSTALL adbc_scanner FROM community;
LOAD adbc_scanner;

-- Local Hardcharger started with password change-me.
CREATE SECRET hardcharger_secret (
    TYPE adbc,
    SCOPE 'hardcharger://localhost?tls=false',
    driver 'hardcharger',
    uri 'hardcharger://localhost?tls=false',
    username 'hardcharger',
    password 'change-me'
);
ATTACH 'hardcharger://localhost?tls=false' AS hc (TYPE adbc);
SHOW ALL TABLES;

SELECT * FROM adbc_scan(
    'hc', 'SELECT 42 AS answer, CAST(? AS VARCHAR) AS greeting',
    params := row('hello')
);
-- answer: 42, greeting: hello
```

Run it with the DuckDB CLI, or paste it into any DuckDB 1.5.6 session:

```console test env=duckdb-adbc title="Run it"
$ duckdb -f query-farm.sql
┌─────────┐
│ Success │
│ boolean │
├─────────┤
│ true    │
└─────────┘
…
┌────────┬──────────┐
│ answer │ greeting │
│ int32  │ varchar  │
├────────┼──────────┤
│     42 │ hello    │
└────────┴──────────┘
```

For a TLS server, replace both URIs with `hardcharger://your-server:31337` (TLS is the default).
Tested with DuckDB 1.5.6.

[Query.Farm docs](https://query.farm/products/extensions/adbc_scanner/) ·
[Community extension](https://duckdb.org/community_extensions/extensions/adbc_scanner) ·
[Driver setup](https://github.com/gizmodata/hardcharger-adbc#readme)

### DuckDB ADBC (Columnar)

Use Columnar.tech's `adbc` community extension with a reusable Hardcharger connection profile. Run
it in its own DuckDB session: it and `adbc_scanner` both register `TYPE adbc`.

Install the DuckDB CLI and the driver, register the driver (or install it with the one-line
installer, as for `adbc_scanner` above), and make a directory for profiles:

```bash title="Install"
pip install duckdb-cli==1.5.6 adbc-driver-hardcharger
```

```console test env=duckdb-adbc server=none title="Register the driver"
$ python -m adbc_driver_hardcharger.manifest
…/.config/adbc/drivers/hardcharger.toml
$ mkdir -p adbc-profiles
```

Save the connection profile as `adbc-profiles/hardcharger.toml`. It reads the credentials from
environment variables:

```toml test file=adbc-profiles/hardcharger.toml server=none title="adbc-profiles/hardcharger.toml"
profile_version = 1
driver = "hardcharger"

[Options]
uri = "hardcharger://localhost?tls=false"
username = "{{ env_var(HARDCHARGER_USERNAME) }}"
password = "{{ env_var(HARDCHARGER_PASSWORD) }}"
```

Save this as `columnar.sql`. SQL inside `read_adbc()` runs on the server; `ATTACH` lets you browse
the server's tables and join them with local data:

```sql test file=columnar.sql server=none title="columnar.sql"
INSTALL adbc FROM community;
LOAD adbc;

SELECT * FROM read_adbc(
    'profile://hardcharger', 'SELECT 42 AS answer'
);
-- answer: 42

ATTACH 'profile://hardcharger' AS hc (TYPE adbc);
SHOW ALL TABLES;
-- Query your remote tables as hc.main.your_table.
```

Point the extension at the profile directory, set the credentials and run it:

```console test env=duckdb-adbc title="Run it"
$ export ADBC_PROFILE_PATH="$PWD/adbc-profiles"
$ export HARDCHARGER_USERNAME='hardcharger'
$ export HARDCHARGER_PASSWORD='change-me'
$ duckdb -f columnar.sql
┌────────┐
│ answer │
│ int32  │
├────────┤
│     42 │
└────────┘
…
```

Filters on attached tables run locally, so put filters and aggregations inside `read_adbc()` to
reduce the data on the server. The extension uses autocommit and does not run concurrent ADBC
operations in one process. For TLS, remove `?tls=false` and set your server's host in the profile.
Tested with DuckDB 1.5.6.

[Columnar docs](https://github.com/columnar-tech/duckdb-adbc-client#readme) ·
[Community extension](https://duckdb.org/community_extensions/extensions/adbc) ·
[Connection profiles](https://github.com/gizmodata/hardcharger-adbc#readme)
