[`@gizmodata/warp-sql`](https://github.com/gizmodata/warp-sql-js) is a TypeScript client for Warp
SQL. It runs wherever `fetch` does (Node, browsers, Deno, Bun, Cloudflare Workers) with no native
code, and returns [`apache-arrow`](https://arrow.apache.org/docs/js/) Tables or streams of record
batches.

<Aside type="caution" title="Preview">
The client is internal and unreleased (0.1.0), and not on npm yet. Until it is, build it from
[gizmodata/warp-sql-js](https://github.com/gizmodata/warp-sql-js): `npm ci && npm run build && npm pack`,
then `npm install ./gizmodata-warp-sql-0.1.0.tgz apache-arrow`. A `hardcharger://` URL scheme is
planned; until then use `warp://host:31337`.
</Aside>

## Query, stream, ingest

```js test
import { tableFromArrays } from 'apache-arrow';
import { WarpSqlError, connect } from '@gizmodata/warp-sql';

const conn = await connect({ url: 'warp://localhost:31337?tls=false', username: 'hardcharger', password: 'change-me' });

// A query with a bind parameter: an Arrow Table back.
const table = await conn.query('SELECT 42 AS answer, ?::VARCHAR AS greeting', ['hello']);
console.log(table.toArray().map((row) => row.toJSON()));

// A big result, streamed batch by batch (and read over several connections at once).
let rows = 0;
for await (const batch of conn.stream('SELECT * FROM range(10000000)')) rows += batch.numRows;
console.log(`streamed ${rows} rows`);

// Bulk ingest from Arrow, then a prepared statement run once per row.
await conn.ingest('events', tableFromArrays({ id: Int32Array.from([1, 2, 3]) }), { mode: 'replace' });
const insert = await conn.prepare('INSERT INTO events VALUES (?)');
console.log(`inserted ${await insert.executeBatch([[4], [5]])} rows`);

// Errors carry the server's code; an AbortSignal cancels the statement on the server.
try {
  await conn.query('SELECT sum(a.range * b.range) FROM range(100000000) a, range(100000) b', undefined, {
    signal: AbortSignal.timeout(1000),
  });
} catch (err) {
  if (!(err instanceof WarpSqlError)) throw err;
  console.log(`${err.code}: ${err.message}`);
}

await conn.close();
```

```text output
[ { answer: 42, greeting: 'hello' } ]
streamed 10000000 rows
inserted 2 rows
statement_timeout: the operation timed out (its AbortSignal fired)
```

| Call | Returns |
|---|---|
| `connect({ url, username, password })` (or `token`, `tokenProvider`, `subjectToken` for SSO) | a `Connection` |
| `conn.query(sql, params?, options?)` | an Arrow `Table` (empty for DDL and DML) |
| `conn.stream(sql, params?, options?)` | a stream to `for await` over: `schema()`, `rowsAffected()`, `toTable()`, `close()` |
| `conn.execute(sql, params?)` | the rows changed |
| `conn.prepare(sql)` | a prepared statement: `query`, `stream`, `execute`, `executeBatch(rows)`, `close()` |
| `conn.ingest(table, data, { mode, catalog, schema, temporary })` | the rows written |
| `conn.metadata.catalogs()`, `tables()`, `columns()`, ... | Arrow tables in Flight SQL's schemas |
| `conn.transaction(async (tx) => …)` | commits, or rolls back on a throw |

Statement options (per call, or as defaults in `connect`): `signal`, `async`, `retainResult`,
`statementTimeoutMs`, `queryTag`, `resultPartitions` (8 in Node, 4 in browsers), `resultOrder`,
`ipcCompression: 'zstd'`. Every error is a `WarpSqlError` with the server's stable `code`,
`status`, `sqlstate` and `requestId`. A result stream that ends without Arrow's end-of-stream
marker throws: a short table is never taken for a complete one.

## TLS

In Node, Deno and Bun, `connect({ url: 'warp://db.example.com:31337', tls: { ca, cert, key } })`
takes PEM text for a private CA and mutual TLS. Browsers use the system's trust store.

## In the browser

The same code runs in a page. The server must allow the page's origin with
[`cors_origins`](/reference/configuration/#cors_origins): an explicit list, off by default, never `*`:

```console test profile=cors
$ curl -s -o /dev/null -D - -X OPTIONS localhost:31337/warp/v1/auth/token \
    -H 'Origin: https://app.example.com' -H 'Access-Control-Request-Method: POST' \
    | grep -i '^access-control-allow-origin' | tr -d '\r'
Access-Control-Allow-Origin: https://app.example.com
$ curl -s -o /dev/null -D - -X OPTIONS localhost:31337/warp/v1/auth/token \
    -H 'Origin: https://elsewhere.example.com' -H 'Access-Control-Request-Method: POST' \
    | grep -i '^access-control-allow-origin' || echo "no CORS headers: the browser refuses"
no CORS headers: the browser refuses
```

- Credentials are bearer tokens in a header, never cookies, so cross-site request forgery has
  nothing to ride on. Keep tokens in memory, not in `localStorage`.
- Serve the page and Hardcharger over HTTPS: browsers block mixed content.
- For people who sign in with your identity provider, pass its ID token as `subjectToken`
  ([SSO](/guides/sso/)).

## Without the client

Warp SQL is plain HTTP, so `fetch` and `apache-arrow` alone work too, as in
[your first query](/get-started/first-query/) and the [plain HTTP page](/clients/http/).
