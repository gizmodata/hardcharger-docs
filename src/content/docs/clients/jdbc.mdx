`hardcharger-jdbc` is a JDBC 4.2 driver: one jar for Java 17 and later, with no gRPC, Netty or
protobuf, and no `--add-opens` or other JVM options. It accepts `jdbc:hardcharger://` URLs and
is a thin layer on the Chargewire JDBC driver, which streams results batch by batch.

## Connect

```
jdbc:hardcharger://host[:port][/catalog][?key=value&...]
```

The port defaults to 31337 (443 for a GizmoData Cloud host, `gizmodata.com` or a name under it,
from 2.4.0; 2.4.1 also takes such a name with a final dot), and TLS is on unless `useEncryption=false`. Options can also follow
semicolons or come in the `Properties`; keys are case-insensitive.

```java test
Properties properties = new Properties();
properties.setProperty("user", "hardcharger");
properties.setProperty("password", "change-me");
properties.setProperty("useEncryption", "false"); // plain HTTP on localhost
try (Connection connection = DriverManager.getConnection("jdbc:hardcharger://localhost", properties)) {
  DatabaseMetaData meta = connection.getMetaData();
  System.out.println(meta.getDatabaseProductName() + " / " + meta.getDriverName());

  try (Statement statement = connection.createStatement()) {
    statement.execute("CREATE TABLE trips (id INTEGER, city VARCHAR, miles DECIMAL(5, 1))");
  }
  try (PreparedStatement insert = connection.prepareStatement("INSERT INTO trips VALUES (?, ?, ?)")) {
    String[] cities = {"Boston", "Denver", "Austin"};
    double[] miles = {12.5, 30.0, 8.5};
    for (int i = 0; i < cities.length; i++) {
      insert.setInt(1, i + 1);
      insert.setString(2, cities[i]);
      insert.setBigDecimal(3, java.math.BigDecimal.valueOf(miles[i]));
      insert.addBatch();
    }
    insert.executeBatch(); // one request for the whole batch
  }
  try (PreparedStatement query = connection.prepareStatement("SELECT city, miles FROM trips WHERE miles > ? ORDER BY miles DESC")) {
    query.setBigDecimal(1, new java.math.BigDecimal("10"));
    try (ResultSet rows = query.executeQuery()) {
      while (rows.next()) {
        System.out.println(rows.getString("city") + " " + rows.getBigDecimal("miles"));
      }
    }
  }
}
```

```text output
Hardcharger / Hardcharger JDBC Driver
Denver 30.0
Boston 12.5
```

## Properties

| Property | Default | Meaning |
|---|---|---|
| `user`, `password` | | Password sign-in; any character is allowed in the password |
| `token` | | A Hardcharger access token to send as is |
| `subjectToken` | | An identity provider's token for the `token_exchange` grant ([SSO](/guides/sso/)) |
| `authType` | `password` | `oauth_browser` (alias `external`): the server's [browser sign-in](/guides/sso/#browser-sign-in), which opens your browser and waits |
| `catalog`, `schema` | server's | The session's starting catalog (also the URL path) and schema |
| `useEncryption` | `true` | `false` for plain HTTP |
| `tlsRootCerts` | | PEM file of CA certificates to trust |
| `trustStore`, `trustStorePassword` | | JKS or PKCS#12 trust store |
| `useSystemTrustStore` | `true` | Trust the JDK's CAs (and the macOS keychain's or Windows' where the JDK reads them) |
| `clientCertificate`, `clientKey` | | Mutual TLS: PEM certificate and unencrypted key (PKCS#8, PKCS#1 RSA or SEC1 EC) |
| `disableCertificateVerification` | `false` | Accept any certificate. Development only. |
| `connectTimeout` | `30000` | Milliseconds to connect |
| `networkTimeout` | `0` | Milliseconds to wait for each response's headers; every request but discovery waits at least 30 s ([a cluster that resumes](#a-stopped-cluster-that-resumes)) |
| `resumeTimeout` | `600` | Seconds to keep retrying while a stopped cluster resumes (`server_resuming`); `0` reports the first such answer at once |
| `async` | `false` | Submit, long-poll, fetch: for long queries behind proxies |
| `retainResults` | server's | `true` keeps results on the server, so a broken download resumes |
| `ipcCompression` | `auto` | `lz4_frame` on a near link, `zstd` on a far one; or `lz4_frame`, `zstd`, `none` |
| `resultPartitions` | `32` | Read a large result over up to n connections at once ([partitions](/concepts/chargewire/#partitioned-results)); `1`: one stream |
| `resultOrder` | `preserve` | `any`: rows in arrival order |
| `resultBufferSize` | `134217728` | Bytes an unread result may buffer when another statement needs its session |

Per statement: `statement.unwrap(com.gizmodata.chargewire.jdbc.ChargewireStatement.class).setResultPartitions(8)`.

## A stopped cluster that resumes

A GizmoData Cloud cluster with auto-resume stops while nobody uses it and starts again at the
next sign-in. While it starts, its address answers `503 server_resuming` with `Retry-After`, and
the driver (2.3.0 and later) waits and sends the same request again, the sign-in included, so
`getConnection` takes longer and then returns a working connection:

- It waits the `Retry-After` (3 s without one, at least 1 s, at most 60 s), until `resumeTimeout`
  (600 s by default) runs out; then the error has SQLSTATE `08001` and code `server_resuming`.
  `resumeTimeout=0` turns the retries off.
- A resuming cluster may hold an answer for up to 25 s, so every request but discovery waits at
  least 30 s for its answer, whatever `connectTimeout` or `networkTimeout` say.
- `isValid(timeout)` and a statement's query timeout stop the retries at their own limit, and
  `cancel()` ends them. Closing a connection, statement or result doesn't wait.
- A connection pool's own connection timeout may need to allow for a resume.

A server with nothing in front of it never answers `server_resuming`, so nothing changes for one.

## How statements run

- Results stream batch by batch; nothing loads a whole result into memory.
- `setQueryTimeout` becomes a server-side timeout, and `cancel()` cancels on the server.
- Closing a `ResultSet` early stops the query on the server.
- Run one statement's result to its end before the next statement on the same connection, or the
  driver buffers the unread rest (up to `resultBufferSize`).
- Prepared statements are prepared on the server; parameters travel as Arrow, so decimals,
  timestamps and binaries are exact. `executeBatch()` sends the whole batch in one request.
- If the server loses the session (idle eviction, restart), the driver opens a new one, replays
  catalog, schema and autocommit, re-prepares prepared statements, and warns. Inside a
  transaction the statement fails with SQLSTATE `08007` instead.

Not supported: generated keys (use `INSERT ... RETURNING`), savepoints, stored procedures,
scrollable or updatable result sets, and bulk ingest (use `executeBatch()`, or
[Python or HTTP](/guides/bulk-ingest/)).

## Errors

Server errors become the `SQLException` subclass their SQLSTATE calls for, with the HTTP status as
the vendor code. `com.gizmodata.chargewire.jdbc.ChargewireProblem.codeOf(e)` returns the server's stable
code (`sql_error`, `statement_timeout`, ...).

```java test
Properties properties = new Properties();
properties.setProperty("user", "hardcharger");
properties.setProperty("password", "change-me");
properties.setProperty("useEncryption", "false");
try (Connection connection = DriverManager.getConnection("jdbc:hardcharger://localhost", properties);
     Statement statement = connection.createStatement()) {
  statement.executeQuery("SELECT * FROM no_such_table");
} catch (SQLException e) {
  System.out.println(e.getSQLState() + " " + com.gizmodata.chargewire.jdbc.ChargewireProblem.codeOf(e));
}
```

```text output
42P01 sql_error
```

## DBeaver

<Steps>

1. **Database > Driver Manager > New.**
2. On **Settings**: driver name `Hardcharger`; class name
   `com.gizmodata.hardcharger.jdbc.HardchargerDriver`; URL template
   `jdbc:hardcharger://{host}[:{port}][/{database}]`; default port `31337`.
3. On **Libraries**: **Add File**, pick `hardcharger-jdbc.jar`, then **Find Class**: it shows
   `com.gizmodata.hardcharger.jdbc.HardchargerDriver`. Click **OK**.
4. **Database > New Database Connection**, choose **Hardcharger**, and enter the host, port, user
   and password.
5. On **Driver properties**: `useEncryption` = `false` for a server without TLS, or
   `tlsRootCerts` for a private CA.
6. **Test Connection**, then **Finish**.

</Steps>

No JVM options are needed. Keep DBeaver's default of a separate connection for metadata reads.
Other JDBC tools (IntelliJ, DbVisualizer, SQuirreL, BI tools) take the same jar, class name and
URL.

<Aside type="note">
On JDK 24 and later the JVM prints a one-time warning about `sun.misc.Unsafe`, which Arrow uses;
`--sun-misc-unsafe-memory-access=allow` silences it.
</Aside>
