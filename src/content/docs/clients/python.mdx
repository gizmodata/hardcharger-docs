`adbc-driver-hardcharger` is Hardcharger's Python driver: a [DB-API 2.0](https://peps.python.org/pep-0249/)
module whose results are Arrow tables. It is a thin layer on the Chargewire ADBC driver (written in
Go), which does the work: Arrow streaming, bind parameters, bulk ingest, partitioned results,
cancel, retries and TLS. The Hardcharger layer adds `hardcharger://` URIs, query and session
tags, `hardcharger.*` settings and browser sign-in.

## Install

```bash
pip install adbc-driver-hardcharger
```

## Connect and query

```python test
from adbc_driver_hardcharger import dbapi as hardcharger

with hardcharger.connect(uri="hardcharger://localhost?tls=false",
                         username="hardcharger", password="change-me") as conn:
    with conn.cursor() as cur:
        cur.execute(operation="CREATE TABLE trips AS SELECT * FROM (VALUES (1, 'Boston', 12.5), (2, 'Denver', 30.0)) t(id, city, miles)")
        cur.execute(operation="SELECT city, miles FROM trips WHERE miles > ? ORDER BY miles", parameters=[10])
        table = cur.fetch_arrow_table()          # a pyarrow.Table
        print(table.to_pylist())
        cur.execute(operation="SELECT count(*) FROM trips")
        print(cur.fetchone())                    # DB-API tuples work too
```

```text output
[{'city': 'Boston', 'miles': Decimal('12.5')}, {'city': 'Denver', 'miles': Decimal('30.0')}]
(2,)
```

- `fetch_arrow_table()` reads the whole result as Arrow; `fetch_record_batch()` returns a
  `RecordBatchReader` that streams it; `fetchone()`, `fetchmany()` and `fetchall()` give tuples.
- Parameters are positional (`?`), sent as values, never spliced into the SQL.
- `executemany()` runs a statement once per parameter row, in one request.
- Connections are in autocommit mode by default; `connect(autocommit=False)` starts a transaction
  that `conn.commit()` or `conn.rollback()` ends.

## URIs

| URI | Means |
|---|---|
| `hardcharger://host` | HTTPS to `host:31337` |
| `hardcharger://host:port` | HTTPS to another port |
| `hardcharger://host?tls=false` | Plain HTTP (your own machine) |
| `hardcharger://host:port/custom/prefix` | The protocol is mounted under `/custom/prefix` |
| `chargewire://…`, `https://…`, `http://…` | The Chargewire driver's own spellings |

Credentials never go in the URI. `connect()` also takes `catalog=` and `db_schema=` for the
session's starting point.

## Connection profiles

ADBC connection profiles keep reusable connection options in TOML. First register the library
installed by this Python environment so a profile's `driver = "hardcharger"` can find it:

```bash
python -m adbc_driver_hardcharger.manifest
```

Save a profile as `prod.toml` in a directory listed in `ADBC_PROFILE_PATH`:

```toml
driver = "hardcharger"
uri = "hardcharger://db.example.com:443"
username = "analyst"
password = { env = "HARDCHARGER_PASSWORD" }
```

Set `HARDCHARGER_PASSWORD` in your environment, then connect by name or absolute file path:

```python
with hardcharger.connect(profile="prod") as conn:
    with conn.cursor() as cur:
        cur.execute(operation="SELECT 42")
        print(cur.fetchone())
```

`uri="profile://prod"` also works. Explicit connection arguments override profile options.
Profiles are resolved by the ADBC driver manager; the native Go driver does not read TOML itself.

## TLS

```python
hardcharger.connect(uri="hardcharger://db.example.com", username="joe", password="…",
                    tls_root_certs="ca.crt",            # a private CA (a path or PEM text)
                    tls_client_cert="client.crt",       # mutual TLS
                    tls_client_key="client.key")
```

The [TLS guide](/guides/tls/) runs these against a real server. `tls_skip_verify=True` is for
your own machine only.

## Tags and settings

```python test
from adbc_driver_hardcharger import dbapi as hardcharger

with hardcharger.connect(uri="hardcharger://localhost?tls=false", username="hardcharger", password="change-me",
                         session_tag={"app": "nightly-etl"}, query_tag={"job": "load-orders"},
                         settings={"query_timeout": 600}) as conn:
    print(conn.current_user(), conn.server_version())
    print(conn.get_setting(name="query_timeout"))
    conn.set_setting(name="query_timeout", value=60)
    print(conn.get_setting(name="query_timeout"))
    conn.reset_setting(name="query_timeout")
    conn.set_query_tag(tag={"job": "refresh-rollups"})    # every later statement
    conn.set_query_tag(tag=None)                            # no tag
```

```text output
hardcharger …
600
60
```

Tags are recorded in [instrumentation](/guides/instrumentation-and-audit/); `settings()` returns
every `hardcharger.*` setting as an Arrow table. A bad setting name or value fails `connect()`.

## Large results

```python test
from adbc_driver_hardcharger import dbapi as hardcharger

with hardcharger.connect(uri="hardcharger://localhost?tls=false", username="hardcharger", password="change-me",
                         db_kwargs={"adbc.chargewire.statement.result_partitions": "8",
                                    "adbc.chargewire.statement.result_order": "any"}) as conn:
    with conn.cursor() as cur:
        cur.execute(operation="SELECT * FROM range(20000000) t(i)")
        total = 0
        for batch in cur.fetch_record_batch():   # streams; nothing is held in memory
            total += batch.num_rows
        print(total)
```

```text output
20000000
```

| Option (`db_kwargs`, or per statement) | Default | Does |
|---|---|---|
| `adbc.chargewire.statement.result_partitions` | `8` | Read a large result over up to n connections at once ([partitions](/concepts/chargewire/#partitioned-results)); `1`: one stream. Small results are one stream anyway |
| `adbc.chargewire.ingest.parts` | `8` | Send a bulk load of two batches or more over up to n connections at once ([partitioned uploads](/guides/bulk-ingest/#partitioned-uploads)); `1`: one stream, in the upload's order |
| `adbc.chargewire.statement.result_order` | `preserve` | `any`: batches in arrival order (faster when order doesn't matter) |
| `adbc.chargewire.ipc_compression` | `none` | `zstd` for slow links |
| `adbc.chargewire.statement.async` | `false` | Submit, poll, fetch: for long queries behind proxies |
| `adbc.chargewire.statement.retain_result` | server's | Keep results on the server so a broken download resumes |
| `adbc.chargewire.statement.timeout_seconds` | none | The server cancels the statement after this long |
| `adbc.chargewire.retry.max_attempts` | `4` | Sends of a request that is safe to repeat |
| `adbc.chargewire.session.reconnect` | `true` | Replace a session the server lost, and say so |

## Bulk ingest

`cur.adbc_ingest(table_name=…, data=…, mode=…)` loads a `pyarrow.Table`, a `RecordBatchReader`
or any Arrow-compatible object. See [Bulk ingest](/guides/bulk-ingest/).

## Errors

The module has DB-API's exception classes (`hardcharger.Error`, `DatabaseError`,
`ProgrammingError`, `OperationalError`, ...). The message carries the server's code, HTTP status,
request id and SQLSTATE:

```python test
from adbc_driver_hardcharger import dbapi as hardcharger

with hardcharger.connect(uri="hardcharger://localhost?tls=false", username="hardcharger", password="change-me") as conn:
    with conn.cursor() as cur:
        try:
            cur.execute(operation="SELECT * FROM no_such_table")
        except hardcharger.Error as e:
            print(type(e).__name__, e.sqlstate)
```

```text output
… 42P01
```

The [error code reference](/reference/errors/) lists the codes.

## Cancel

Ctrl-C while a query runs cancels it on the server. From another thread, `cur.adbc_cancel()` does
the same.

## Sign in with SSO

`connect(username="token", password=<ID token>)` signs in with an identity provider's token, and
`connect(auth_type="external")` runs the browser sign-in. See [SSO](/guides/sso/).

## A server from Python

`pip install hardcharger` is the **server** for Python: it downloads `hardcharger-server` for your
platform, checks it and runs it on a free port, which makes a real server one line away in tests
and notebooks.

```python test server=none release
import hardcharger

with hardcharger.Server() as server, server.connect() as conn, conn.cursor() as cur:
    cur.execute(operation="SELECT 42 AS answer")
    print(cur.fetchone())
```

```text output
(42,)
```

`Server()` uses an in-memory database and a generated password (`server.password`); pass
`database=`, `password=`, `tls_cert=`/`tls_key=`, `extra_args=[...]` or `env={...}` for more.
`pip install "hardcharger[adbc]"` installs it with this driver.
