This page takes the command-line server from install to a first query, in three steps. For
every other way to run Hardcharger, starting with **GizmoData Cloud** (nothing to install),
and including the desktop app and the phone apps, see **[Install](/get-started/install/)**.

## 1. Get the server

Pick one way to get the command-line server, then start it with an administrator password:

<Tabs syncKey="install">
<TabItem label="Installer">

macOS on Apple silicon and Linux (x86-64 or arm64, glibc 2.28 or newer: RHEL, Rocky and Alma Linux 8,
Debian 10, Ubuntu 20.04, Amazon Linux 2023):

```console test server=none release
$ curl https://install.hardcharger.gizmodata.com | sh
…
$ ~/.hardcharger/bin/hardcharger-server --version
Hardcharger …
```

The installer puts every version under `~/.hardcharger/versions/` and links the current one
into `~/.hardcharger/bin`; add that directory to your `PATH`. It checks each download against
the release's SHA-256 before switching. `HARDCHARGER_VERSION=0.3.0` installs a given version,
and `sh -s -- --list` lists what you have. For every option (another install
directory, `--modify-path` to update your `PATH`, uninstalling, the Windows PowerShell installer),
see [hardcharger-install](https://github.com/gizmodata/hardcharger-install).

Start the server:

```bash
HARDCHARGER_ADMIN_PASSWORD='change-me' ~/.hardcharger/bin/hardcharger-server --database my.duckdb
```

</TabItem>
<TabItem label="Homebrew">

On macOS 15+ with Apple silicon, or Linux on x86-64 or arm64, install the server and CLI
from GizmoData's [Homebrew tap](https://github.com/gizmodata/homebrew-tap):

```bash
brew install gizmodata/tap/hardcharger
hardcharger-server --version
```

Start the server with your database and administrator password:

```bash
HARDCHARGER_ADMIN_PASSWORD='change-me' hardcharger-server --database my.duckdb
```

To update an existing installation, run `brew update` followed by `brew upgrade hardcharger`.
The release workflow checks installation and a query through the CLI on all three platforms
before publishing the formula update. For the macOS app, see
[desktop installation](/guides/desktop-app/#install-with-homebrew-on-macos).

</TabItem>
<TabItem label="Docker">

Images are multi-architecture (`linux/amd64`, `linux/arm64`):

```bash test server=self background cleanup="docker rm -f hardcharger" timeout=180
docker run --rm --name hardcharger -p 31337:31337 -p 31338:31338 \
  -e HARDCHARGER_ADMIN_PASSWORD='change-me' \
  ghcr.io/gizmodata/hardcharger:latest
```

Port 31337 speaks Chargewire; 31338 answers `/health`.

</TabItem>
<TabItem label="Binaries">

Linux (x86-64, arm64) and macOS (Apple silicon) tarballs, and Windows zips and MSIs, are attached to every
[release](https://github.com/gizmodata/hardcharger/releases/latest). Download the one for your
platform, then unpack it:

```bash test server=self release stop
case "$(uname -sm)" in
  "Linux x86_64")  PLATFORM=linux-amd64 ;;
  "Linux aarch64") PLATFORM=linux-arm64 ;;
  "Darwin arm64")  PLATFORM=macos-arm64 ;;
esac
tar -xzf "hardcharger-$PLATFORM.tar.gz"
mv "hardcharger-$PLATFORM" hardcharger
```

```bash test server=self background wait=http://127.0.0.1:31337/chargewire/v1/health
HARDCHARGER_ADMIN_PASSWORD='change-me' ./hardcharger/bin/hardcharger-server --database my.duckdb
```

On Windows (x64 and arm64), unzip `hardcharger-windows-amd64.zip` or `-arm64.zip` in
PowerShell, or run `Hardcharger-windows-amd64.msi` / `-arm64.msi`, which installs under Program
Files and puts `hardcharger-server.exe` and the `hardcharger.exe` client on the `PATH`. The
executables are single files that need no Visual C++ Redistributable. Ctrl+C or Ctrl+Break stops
the server as `SIGINT` or `SIGTERM` does elsewhere.

```powershell
Expand-Archive hardcharger-windows-amd64.zip -DestinationPath .
$env:HARDCHARGER_ADMIN_PASSWORD = 'change-me'
.\hardcharger-windows-amd64\bin\hardcharger-server.exe --database my.duckdb
```

</TabItem>
<TabItem label="Python">

The `hardcharger` Python package runs the server for you. It downloads the release for your
platform on first use, checks its SHA-256, caches it and starts it on a free port:

```python test server=none release
import hardcharger

with hardcharger.Server(password="change-me") as server:
    print(server.uri)
```

```text output
hardcharger://127.0.0.1:…?tls=false
```

```bash
pip install hardcharger
```

See [Python (ADBC)](/clients/python/) for `server.connect()`.

</TabItem>
</Tabs>

<Aside type="tip">
Pass the password in the `HARDCHARGER_ADMIN_PASSWORD` environment variable, not as a flag:
flags show up in process listings. The administrator's user name is `hardcharger` unless you
set `--admin-username`.
</Aside>

## 2. Check that it is up

```console test server=none
$ curl -s localhost:31337/chargewire/v1/health
{"status":"serving"}
```

The health endpoint needs no credentials. For load balancers and Kubernetes probes, also
serve it on its own plaintext port with `--health-port 31338` (the Docker image does). Port
31337 describes itself at `/chargewire`:

```console test server=none
$ curl -s localhost:31337/chargewire | jq -r '.server.name, .protocol'
Hardcharger
chargewire
```

## 3. Run a query

Chargewire is plain HTTP, so `curl` is enough. Get a token, open a session, run SQL:

```bash test server=none
TOKEN=$(curl -s localhost:31337/chargewire/v1/auth/token -H 'Content-Type: application/json' \
  -d '{"grant_type": "password", "username": "hardcharger", "password": "change-me"}' | jq -r .access_token)
SESSION=$(curl -s localhost:31337/chargewire/v1/sessions -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{}' | jq -r .session_id)
curl -s localhost:31337/chargewire/v1/sessions/$SESSION/statements -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -d '{"sql": "SELECT 42 AS answer"}' | jq .result.kind
```

```text output
"rows"
```

That answer is a statement document. Ask for `Accept: application/vnd.apache.arrow.stream`
and the rows themselves arrive as an Arrow IPC stream in the same response; the
[plain HTTP client page](/clients/http/) shows both.
