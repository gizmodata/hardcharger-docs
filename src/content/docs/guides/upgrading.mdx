Hardcharger follows [semantic versioning](https://semver.org). Before 1.0, a minor version
(`0.3` to `0.4`) may change options or behavior; the [release notes](/reference/release-notes/)
say what, under **Changed**. Patch versions only fix things.

<Steps>

1. **Read the release notes** for every version between yours and the new one. Look for renamed
   options (an unknown option stops the server at startup, so you'll know at once) and changed
   defaults.

2. **Check the database file format.** DuckDB 2.0 reads files written by DuckDB 1.x. An existing
   plain DuckDB database retains its format unless you request an upgrade.
   **v2.1.0+ removes Hardcharger’s DuckLake metadata compatibility patch:** upstream DuckLake
   can upgrade a DuckDB metadata file on writes/checkpoints so older readers cannot reopen
   it. Back up metadata before upgrading. `storage_version` does not override DuckLake’s
   metadata choice. See [extension and metadata compatibility](/guides/extensions/#ducklake-metadata-compatibility).

3. **Upgrade.**

   - Installer: `curl https://install.hardcharger.gizmodata.com | HARDCHARGER_VERSION=0.3.0 sh`
     installs the version next to the others and switches to it. Restart the server.
   - Docker or Kubernetes: change the image tag. Pin versions (`:0.3.0`), not `:latest`, so
     that a restart never upgrades by surprise.
   - Python: `pip install --upgrade hardcharger` downloads the server version the package pins.

4. **Restart gracefully.** On `SIGTERM` the server stops taking new work and lets running
   statements finish ([graceful shutdown](/guides/statement-control/#graceful-shutdown)). With
   several replicas, upgrade one at a time: drivers move to a new session when theirs goes away.

5. **Check** that the new version runs: `SELECT HARDCHARGER_VERSION()`, the health endpoint, and
   your metrics.

</Steps>

## Upgrading from 2.2

Hardcharger's protocol is now named Chargewire. The server answers at `/chargewire` and
`/chargewire/v1/...`, and it keeps answering drivers and clients released before the rename in
the spelling they use.

- **Drivers and clients from 2.2 and earlier keep working** with the new server, unchanged,
  except that they show no column defaults (JDBC's `COLUMN_DEF`, for one): the server sends a
  column's default only under the Chargewire metadata key. Upgrade the driver to see them again.
- **The new drivers work with 2.2 servers too**, at the default base path, so servers and drivers
  can be upgraded in either order.
- **Connection strings keep working.** `hardcharger://` URIs, `jdbc:hardcharger://` URLs and the
  `adbc.hardcharger.*` options are unchanged, and the drivers still read `warp://` URIs and
  `adbc.warp.*` option keys, as `chargewire://` and `adbc.chargewire.*`.
- **Single sign-on: register the new redirect URI before upgrading.** When
  [`oauth_redirect_uri`](/reference/configuration/#oauth_redirect_uri) isn't set, the server now
  sends `<oauth_base_url>/chargewire/v1/auth/oauth/callback` to the identity provider. Add that
  URL to the application's allowed redirect URIs (Okta, Microsoft Entra ID and Google all accept
  several), or set `oauth_redirect_uri` to the URL registered there today. The server answers its
  callback at both, so sign-in keeps working through the upgrade.
- **ODBC.** The Hardcharger ODBC Driver keeps its registered name, so its DSNs need no change. A
  DSN or connection string that names the generic Chargewire driver by its earlier registered
  name must name `Chargewire ODBC Driver` instead.
- **A proxy that routes by path** ([behind a load balancer](/guides/load-balancers/)) should pass
  `/chargewire/` as well as `/warp/`: new clients use the first, clients from before the rename
  the second.

## Rolling back

The installer keeps every version you installed, so switching back doesn't download anything:

```bash
curl https://install.hardcharger.gizmodata.com | HARDCHARGER_VERSION=<previous version> sh   # back
curl https://install.hardcharger.gizmodata.com | HARDCHARGER_VERSION=<newer version> sh      # and forward again
```

`--list` shows what is installed, the current version starred:

```console test server=none release
$ curl -s https://install.hardcharger.gizmodata.com | sh > /dev/null 2>&1
$ curl -s https://install.hardcharger.gizmodata.com | sh -s -- --list
Hardcharger versions in …/.hardcharger/versions:
  * … (current)
$ ~/.hardcharger/bin/hardcharger-server --version
Hardcharger …
```

`sh -s -- --uninstall 0.1.2` removes one version.

<Aside type="caution" title="Coming from GizmoSQL">
Moving from GizmoSQL 1.x is a migration, not an upgrade: new names, a new protocol and new
drivers. See [Coming from GizmoSQL](/get-started/coming-from-gizmosql/).
</Aside>
