## How versions work

- Hardcharger follows [semantic versioning](https://semver.org): a major version may change
  options or behavior, a minor version adds to them, and a patch version only fixes things.
- A release candidate (`2.0.0-rc.1`) comes before its release. It is a pre-release: its image
  is tagged with its version (`:2.0.0-rc.1`), never `:latest`.
- The server, the `hardcharger` CLI, the desktop app, the `hardcharger` Python server package,
  and the container image share one base version. Python-only packaging fixes use a `.postN`
  release. The drivers
  ([Python](/clients/python/), [Go](/clients/go/), [JDBC](/clients/jdbc/),
  [JavaScript](/clients/javascript/)) are versioned on their own and speak
  [Chargewire](/concepts/chargewire/), whose protocol version the server reports at `GET /chargewire`
  (`protocol_versions`).
- `HARDCHARGER_VERSION()` and `hardcharger-server --version` report the server's version.
- [Upgrading](/guides/upgrading/) covers moving between versions and rolling back.

## Drivers

The client releases that go with Hardcharger 2.11.0 (each one's GitHub release has its notes).
The Hardcharger drivers are the Chargewire ones under Hardcharger's names, with `hardcharger://`
URIs (port 31337; 443 for a GizmoData Cloud host).

| Client | Chargewire | Hardcharger |
|---|---|---|
| [JavaScript](/clients/javascript/) | `@gizmodata/chargewire` 2.3.5 | `@gizmodata/hardcharger` 2.4.4 |
| ADBC: [Python](/clients/python/), [Go](/clients/go/), [the driver manager](/clients/adbc-driver-manager/) | `chargewire-adbc` 2.2.10 | `hardcharger-adbc` 2.4.9 |
| [JDBC](/clients/jdbc/) | `chargewire-jdbc` 2.2.6 | `hardcharger-jdbc` 2.4.4 |
| ODBC | `chargewire-odbc` 2.4.0 | Hardcharger ODBC Driver 1.5.0 |
| MCP server | | `hardcharger-mcp` 2.4.3 |
| Replication into Hardcharger | | `adbc-replicate-hardcharger` 2.3.1 |

The drivers and the MCP server above connect [lazily](/concepts/chargewire/#a-stopped-server-lazy-connect) to a stopped
GizmoData Cloud cluster (Chargewire 2.4), and their closes, cancels and connection checks never
sign in.
