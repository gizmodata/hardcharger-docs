## How versions work

- Hardcharger follows [semantic versioning](https://semver.org): a major version may change
  options or behavior, a minor version adds to them, and a patch version only fixes things.
- A release candidate (`2.0.0-rc.1`) comes before its release. It is a pre-release: its image
  is tagged with its version (`:2.0.0-rc.1`), never `:latest`.
- The server, the `hardcharger` CLI, the desktop app, the `hardcharger` Python server package,
  and the container image share one base version. Python-only packaging fixes use a `.postN`
  release. The drivers
  ([Python](/clients/python/), [Go](/clients/go/), [JDBC](/clients/jdbc/),
  [JavaScript](/clients/javascript/)) are versioned on their own and speak
  [Chargewire](/concepts/chargewire/), whose protocol version the server reports at `GET /chargewire`
  (`protocol_versions`).
- `HARDCHARGER_VERSION()` and `hardcharger-server --version` report the server's version.
- [Upgrading](/guides/upgrading/) covers moving between versions and rolling back.
